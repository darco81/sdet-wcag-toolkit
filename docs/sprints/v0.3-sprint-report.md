## Architecture decisions

1. **AI agents read source, not stub axe output.** Day-one plan was
   thin LLM wrappers translating axe violations. Killed in 4h after
   the prototype landed flat - see "Pivot architecture" in
   `docs/ARCHITECTURE.md`. The shipping shape: each specialist owns
   a domain (semantic / aria / keyboard / contrast / forms) and reads
   JSX/Vue/Angular/Svelte/Astro/HTML directly via `Read` + `Grep` +
   `Glob`.
2. **Single runtime in public, multi-runtime in Pro.** Public ships
   the CC adapter only (`RuntimeId = 'claude-code'`). OpenCode and
   OpenCode-Ollama adapters stay in Pro alongside scoped audits and
   the auto-fix engine.
3. **Lead orchestrator is pure dispatch + dedupe + score.** No
   per-domain logic in the orchestrator - that lives in the prompts.
   Orchestrator's job is parallel dispatch, JSON parse + zod
   validation, dedupe by `(ruleId, file:line, url)`, severity-weighted
   score aggregation, and grade band.
4. **Grade band is score-derived, not finding-count.** Critical -15,
   serious -10, moderate -5, minor -2; floor at 0. A: 90+, B: 75-89,
   C: 50-74, D: 25-49, F: <25. Scales with severity, not with how
   many low-priority items exist.
5. **Skill = orchestration document, CLI = deterministic engine.**
   Lesson learned 28.04 (see "Post-ship patch" below). The skill
   instructs CC to dispatch Task in-session; the CLI subprocess only
   runs static + dynamic. Don't mix the layers.

## Caveats

- **`--use-ai` from a Bash CLI subprocess silent no-ops outside a CC
  session.** The Lead orchestrator looks up `globalThis.Task` to
  dispatch specialists - `Task` only exists in the CC JS runtime.
  Outside CC, every specialist returns a "tool unavailable" error
  and the audit falls through to static + dynamic only. Works as
  intended when invoked through the `/wcag:audit` skill from inside
  a CC session.
- **Public dispatch is single-runtime.** Pro adds OpenCode and
  Ollama runtimes plus a runtime selector flag.
- **No auto-fix in public.** `/wcag:fix` falls back to a manual
  remediation walkthrough unless the Pro CLI is installed (Pro V0.4
  ships 2 patchers: image-alt and html-lang).
- **Dedupe is shallow.** Same defect flagged by two specialists
  keeps both entries unless the `(ruleId, file:line, url)` key
  matches exactly. Deep semantic dedupe is a v0.5 / Pro feature.

## Post-ship patch (2026-04-28)

Discovered through dogfooding on `portfolio-v2`: `SKILL.md`
instructed CC to invoke the CLI via Bash subprocess with
`--use-ai`, which loses Task context. All 5 specialists silently
errored, audit fell through to static + dynamic only.

Fixed in commit `ebd3a2c`: `SKILL.md` now says "dispatch Task
DIRECTLY from this session, then run CLI for deterministic only".
1 file changed, 0 code changes. Verify on `examples/react-basic`
showed parity with Pro V0.4 alpha.2 baseline (19 unique findings
both runs).

See `docs/sprints/v0.3-skill-refactor-patch.md` for the full
patch report with verify table.
