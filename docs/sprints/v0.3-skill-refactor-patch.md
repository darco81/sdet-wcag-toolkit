# v0.3 patch - skill `/wcag:audit` refactor

**Date:** 2026-04-28
**Type:** bugfix patch (no new features, no version bump - `SKILL.md` only)
**Commit:** `ebd3a2c` - `fix(skill): /wcag:audit dispatches Task directly, no CLI --use-ai loop`

## What happened

v0.3.0 shipped on 2026-04-25 with the `/wcag:audit` skill. Dogfooding on `portfolio-v2`
on 2026-04-28 morning revealed all 5 AI specialists silently failed:

```
! agent semantic-structure returned 1 error(s); findings from other agents kept.
! agent aria-patterns returned 1 error(s); findings from other agents kept.
! agent keyboard-interaction returned 1 error(s); findings from other agents kept.
! agent color-contrast-static returned 1 error(s); findings from other agents kept.
! agent forms-accessibility returned 1 error(s); findings from other agents kept.
```

Root cause: the skill instructed CC to run the CLI via Bash subprocess with `--use-ai`.
Inside Node, the Lead orchestrator looks up `globalThis.Task` to dispatch specialists -
but `Task` only exists in the CC JS runtime, not in a Node child process. Every
specialist returned a "Task tool unavailable" error and the audit fell through to
static + dynamic only (~60% of v0.3 capability).

Net result on `portfolio-v2`: **10 findings instead of expected ~12+ unique with AI tier.**

## What was fixed

`.claude/skills/wcag-audit/SKILL.md` rewritten:

- CC dispatches the 5 specialists DIRECTLY via the Task tool (parallel, single message
  with 5 invocations) from its own session - where `Task` exists.
- CLI subprocess is used only for static + dynamic analysis. `--use-ai` is no longer
  passed.
- Added an explicit "Architecture note" section explaining why we don't route AI
  through the CLI flag.
- Same orchestration shape as the v0.1 `wcag-static-analyze` skill, which was correct.
  v0.3 `wcag-audit` regressed by routing through a CLI flag.

**No code changes.** CLI, runtime adapter, Lead orchestrator, and all 5 agent
definitions are correct and unchanged. Only the orchestration document was wrong.

Diff stat: `1 file changed, 134 insertions(+), 37 deletions(-)`.

## Lesson

**Skill design pattern:** CC orchestrates Task dispatch in-session, CLI provides the
deterministic backbone. Bash subprocess loses Task context, so the CLI shouldn't try
to be the Task entry point.

This pattern was already correct in v0.1's `wcag-static-analyze` skill. v0.3's
`wcag-audit` regressed by routing through a CLI flag. The fix is a one-file revert
of the orchestration document to the v0.1 pattern, generalized to 5 specialists +
dynamic.
