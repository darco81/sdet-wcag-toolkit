# Sprint 4 report - v0.4 multi-page audit

Dates (calendar): 2026-04-29 (single-day sprint, 8 atomic commits
across 8 phases on `feat/v0.4-multi-page` branch)
Releases: v0.4.0 - multi-page audit with 4-strategy auto-discovery

## What landed

The v0.4 audit chains a discovery layer in front of the dynamic
tester and a deduper after it. Running without `--multi-page` is
byte-identical to v0.3 single-page behavior - backward compat strict.

### New package (1)

- **`@sdet-wcag-toolkit/route-discovery`** - `dispatchRouteDiscovery`
  with auto-fallback chain (default `sitemap → router-scan →
  json-config`; `ai` opt-in only). Strategy registry exposes a single
  injectable interface so tests substitute fakes and the Pro tier
  can swap individual strategies without forking. 4 strategies:
  - **`sitemap`** - fetches `/sitemap.xml`, falls back through
    `sitemap-0.xml` and `sitemap_index.xml`, recurses into
    `<sitemapindex>` (depth cap 5 + cycle protection), skips HTML
    404 fallbacks via content sniff (`<?xml`, `<urlset`,
    `<sitemapindex`), filters default exclusions (`/api/*`,
    `/og/*`, `/feed.xml`, `/rss.xml`, `/sitemap*.xml`, `/llms*.txt`,
    `/robots.txt`), rejects cross-origin `<loc>` entries.
  - **`router-scan`** - package.json deps matrix detects framework
    (priority: nuxt > sveltekit > remix > gatsby > next > astro >
    vue > react-router). Tiny zero-dep recursive walker (`walker.ts`)
    walks framework-specific subtrees with a default ignore set
    (`node_modules`, `dist`, `.next`, `.nuxt`, `.svelte-kit`,
    `.astro`, `.cache`, `public`, `static`). Detectors per framework
    map files to URL paths. Phase 3 ships **Astro, Next.js (App +
    Pages Routers), Vue (vite-plugin-pages)**; SvelteKit, Remix,
    Gatsby, React Router are detected but emit "no detector yet"
    warnings so the dispatcher falls through.
  - **`ai`** - runtime-agnostic strategy with `AiAgentInvoker`
    contract. CLI bridges Claude Code's `TaskInvoker` to the
    invoker shape when `--use-ai` or `--strategy=ai` is set.
    Hand-rolled JSON validator (no zod dep), tagged-union parser
    (`{ kind: 'ok' | 'invalid' }`), `<think>` block stripping.
    Dispatches `.claude/agents/route-discovery-agent.md` which reads
    `package.json` + framework configs and resolves dynamic routes
    via `getStaticPaths` / `generateStaticParams` / content
    collections.
  - **`json-config`** - escape hatch. `wcag.config.json` with
    `audit.baseUrl` (http(s) URL required) + `audit.pages` (string[])
    + optional `audit.exclude` (glob patterns; `*` → `.*`, other
    regex meta escaped) + optional `audit.auth` (`'cookie' |
    'header' | 'storage-state'`). Auth section is parsed end-to-end
    but ignored in the public toolkit; the Pro tier consumes it.
    Auto-detected in cwd or via `--config <path>`.

## Key architectural decisions

1. **AI is opt-in, not in the default fallback chain.** Token spend
   is non-trivial; users get `sitemap → router-scan → json-config`
   for free and `--strategy=ai` (or `--use-ai`) when they want the
   "wow" feature.
2. **Browser reuse across pages, sequential per-page.** Starting
   Chromium per route would dominate the audit time on any
   non-trivial site. Per-page work has to stay sequential because
   the existing runners (keyboard-flow, focus-visibility) share the
   Page and aren't concurrency-safe. Pro tier gets parallelism via
   `BrowserContext`-per-page.
3. **DI seams everywhere.** Walker takes a `DirectoryReader`, AI
   strategy takes an `AiAgentInvoker`, sitemap takes a `SitemapFetcher`,
   json-config takes a file reader, multi-page orchestrator takes a
   `PageAuditFn`. Tests run hermetic and fast (149 route-discovery
   tests in 250ms; orchestrator tests under 100ms without Playwright).
4. **Hand-rolled validators, no zod in route-discovery.** Adds a
   single dep (`fast-xml-parser`) for the sitemap strategy and
   nothing else. Tagged-union parser results (`{ kind: 'ok' | 'invalid' }`)
   force callers to handle both branches at compile time.
5. **Cross-page dedup keys are content-aware.** File+line for
   source-located findings, selector for DOM-located, message as
   last-resort fallback. First occurrence wins as the canonical
   finding so the report ID stays stable across reruns. Skipped
   pages don't contribute (their `findings` array isn't even
   scanned).
6. **Skipped routes always appear in the report.** Users want to
   know what was excluded and why - `dynamic-no-sample`,
   `runner-error`, `max-pages` reasons each surface in their own
   section grouped by category. Heat map shows skipped pages with
   strikethrough so the full discovered set stays visible.

## What's deferred to V0.4 alpha.4 (Pro tier)

Per spec, these are commercial extensions in the
`sdet-wcag-pro` repo:

- **Per-page Playwright trace recording** - Playwright 1.59
  `tracing.start()` per route, `traces/<page-slug>.zip` with DOM
  snapshots + network log + console errors per axe scan.
- **Per-page screenshot sequences** - `screenshots/<page-slug>/<ts>-<action>.png`
  for page load, focus walk start/end, modal open. Bonus: case
  study material (Dariusz gets a visual log of every audit).
- **Authenticated routes** - wires the `audit.auth` section into
  Playwright `storageState` / cookie / header injection. Critical
  for e-commerce daily-use replacement of firmowego toolkita.
- **Parallel page execution** - `--parallel=4` opt-in,
  `BrowserContext`-per-page so runners stay isolated. 20-page audit
  drops from 10 min sequential to ~2.5 min parallel.
- **Per-route specialist routing** - Lead orchestrator routes
  specialists by URL pattern. `/checkout/*` →
  ecommerce-journey + forms-accessibility only; `/blog/*` →
  semantic-structure + heading-order only. Saves AI cost on every
  route.
- **Visual diff for regression auditing** - odiff / pixelmatch on
  pre-fix vs post-fix screenshots. "Did this WCAG fix break the
  layout?" caught at audit time.
